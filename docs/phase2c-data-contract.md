# Phase 2C.0 research data contract

This is an offline, descriptive research contract. It does not define a trading signal, executable return, threshold, or order. The extractor is [`scripts/phase2c_dataset_audit.py`](../scripts/phase2c_dataset_audit.py); it opens both SQLite files with `mode=ro`, enables `query_only`, fixes an `--as-of` time, and emits aggregate JSON only. It does not import the RPC client or load credentials. Production databases and services are not changed.

## Unit, timing, and eligibility

The analytical primary key is **`(launch_id, feature_window_seconds, label_horizon_seconds)`**. One row is one stock-paired launch, one cumulative flow window from launch, and one later Phase 2A market horizon. `launch_id` is the shared foreign key between the two databases. `token_address` and `quote_asset_address` must agree with the launch and both market snapshots. Addresses identify assets; quote-native amounts from different quote assets must not be pooled. `cohort_initial` and `cohort_long` are deterministic launch-address sampling flags, not later performance classes.

The flow feature cutoff is `flow_features.feature_cutoff_at = flow_tracking_targets.tracking_start_at + window_seconds`. The scheduled label time is launch block time plus `outcome_targets.target_age_seconds`; actual label measurement time is `market_snapshots.observed_at`. Supported flow cutoffs are 30, 60, 300, 900, and 3600 seconds. Supported market horizons are T+0, 300, 900, 3600, 21600, and 86400 seconds. T+0 is a baseline, never a later label. A pair is allowed only when `label_horizon_seconds > feature_window_seconds`; its minimum scheduled separation is their difference. Actual label observation must also be strictly later than the feature cutoff. The audit records the minimum observed separation per pair.

The primary outcome is `price_quote(T+H) / price_quote(T+0)` when both snapshots have positive, verified prices in the same quote asset. It is **cumulative T+0-to-H marginal price movement**, not a pure post-cutoff move and not trader realized PnL. `fdv_quote(T+H) / fdv_quote(T+0)` is a separate descriptive outcome when both values are valid. Graduation by H can be studied later as a time-bounded label using the first graduation block timestamp, but current audit screens price multiple only. Label market phase (`curve` or `v4`) is outcome diagnostics, never a predictor. A curve snapshot uses normalized reserve ratio; a V4 snapshot uses normalized `sqrtPriceX96` and records raw active liquidity. Their price metric is comparable within a quote asset but neither is an executable buy/sell quote; V4 raw liquidity is not quote notional.

The **default model/research eligibility is COMPLETE only**. The mature denominator for each pair is a tracked stock-paired launch with a scheduled sampled Phase 2A target at H, whose target due time and flow cutoff are at or before the fixed audit time. The extractor reports one exclusive first exclusion reason per mature candidate. A row then needs a present `flow_features` record with `coverage_quality='complete'`, exact cutoff, present verified T+0/H market snapshots, matching quote identity, positive price, actual label observation after cutoff, baseline observation no later than label, and `flow_features.finalized_at < label observed_at`. The last rule is conservative: it excludes features last rebuilt after the label was measured. `PARTIAL` and `UNAVAILABLE` are reported with their reasons and never imputed into the primary dataset. A missing or not-yet-due label does not become a zero return. Expired `partial` targets remain partial even if the current service is healthy.

Feature values are cumulative **event-time** aggregates from launch to cutoff. Their persisted `finalized_at` can be overwritten on later rebuilds, so a passing row is retrospectively pre-label, **not proof that the feature was available live at the exact cutoff**. Any later live-decision study needs an independent point-in-time availability ledger or reconstruction using `flow_events.observed_at` and contemporaneous coverage proof. The current audit deliberately makes no live-deployability claim.

## Field-level data dictionary

| Field(s) | Table | Meaning and allowed use |
|---|---|---|
| `launches.id`, `tx_hash`, `log_index`, `block_number`, `block_timestamp` | main `launches` | Launch identity and on-chain event time/block. `id` joins Phase 2A/2B. Event identity is `(tx_hash, log_index)`. `detected_at` is collector arrival time, not launch time. |
| `token_address`, `quote_asset_address`, `curve_address`, `launch_type`, `is_stock_quote` | main `launches` | Token, quote pairing, curve, launch type, and stock-quote classification known from launch. `stock_assets.verified`, `stock_ticker`, `updated_at` are mutable reference metadata; use only as annotated diagnostics unless an as-of version is available. |
| `graduations.token_address`, `block_number`, `block_timestamp`, `pool_id` | main `graduations` | Verified curve-to-V4 transition. Earliest graduation at or before cutoff determines **state at cutoff**. A later graduation or pool ID is FUTURE_ONLY for a predictor. |
| `outcome_targets.launch_id`, `target_age_seconds`, `due_at`, `sampling_group`, `sampling_probability` | main `outcome_targets` | Scheduled Phase 2A horizon and deterministic sampling/cohort metadata. `status`, `attempts`, `completed_at`, and `error_code` are outcome-process diagnostics, not predictors. |
| `market_snapshots.observed_at`, `age_seconds`, `delay_seconds`, `market_phase`, `data_quality`, `source_method` | main `market_snapshots` | Actual market observation time, delay, curve/V4 source, and quality. H snapshot fields are FUTURE_ONLY relative to an earlier feature cutoff. |
| `price_quote`, `fdv_quote`, `quote_reserve`, `token_reserve`, `token_supply`, `liquidity_metric_type`, `liquidity_quote_estimate`, `v4_active_liquidity` | main `market_snapshots` | Quote-native marginal price/FDV and phase-specific raw state. Curve `quote_reserve` includes phantom reserve; curve liquidity estimate is real one-sided quote reserve. V4 liquidity is a raw active-liquidity unit, not quote notional. Use as labels or diagnostics at H, not earlier predictors. |
| `flow_tracking_targets.launch_id`, `tracking_start_at`, `tracking_end_at`, `cohort_initial`, `cohort_long`, `launch_block` | flow `flow_tracking_targets` | Flow sampling identity, block-time start, 15m or 1h expiry, and persisted launch-time cohorts. `current_phase`, `graduation_json`, final `status`, and final `coverage_quality` can reflect future information; diagnostics only. |
| `flow_events.chain_id`, `tx_hash`, `log_index`, `phase`, `block_number`, `event_time`, `observed_at`, `removed`, `direction`, `payload` | flow `flow_events` | Canonical raw curve/V4/hook events. Primary event key is `(chain_id,tx_hash,log_index)`. `event_time` is chain block time; `observed_at` is collector arrival. Removed events are excluded from aggregate features. The audit aggregates in SQL and does not load raw payload history. |
| `caller_address`, `recipient_address`, `swap_sender`, `economic_actor` | flow `flow_events` | Distinct on-chain roles, not interchangeable traders. Curve caller can be a router; recipient receives the asset; V4 swap sender can be intermediary. `economic_actor` remains unknown unless independently proved. |
| `flow_features.launch_id`, `window_seconds`, `feature_cutoff_at`, `finalized_at` | flow `flow_features` | Unique `(launch_id,window_seconds)` cumulative window and its last materialization time. `finalized_at` is a timing gate/diagnostic, never a predictor. |
| `coverage_start_at`, `coverage_end_at`, `coverage_quality`, `coverage_reason` | flow `flow_features` | Retrospective continuity evidence. `COMPLETE` is the default eligibility filter; `PARTIAL` is evidence with a gap; `UNAVAILABLE` carries NULL metrics. Quality/reason are diagnostics, not predictive features. |
| `flow_bootstrap.safe_start`, `status`, `completed_head`; `flow_state` recovery cursors; `flow_gaps.reason`, `resolved`, `first_block` | flow proof tables | Audit lineage for contiguous recovery. A completed bootstrap/cursor does not retroactively upgrade a partial feature row; unresolved historical gaps remain preserved. Provider-switch/cutover records identify routing era and switch proof, not market outcomes. |

The six **screened predictor keys** in `flow_features.metrics` are `curve_buy_count`, `curve_sell_count`, `total_directional_event_count`, `v4_core_swap_count`, `unique_buy_recipients`, and `top1_buy_recipient_token_share`. Counts mean decoded, non-removed events within that feature window. `unique_buy_recipients` counts token-receiving addresses, not economic buyers. `top1_buy_recipient_token_share` is the largest recipient's share of bought tokens and is NULL if no bought tokens; it is not holder concentration. V4 swap count is a core swap-event count, not a number of independent economic trades. No numeric metric is silently imputed.

Other persisted metrics are available but are **not screened in the pooled audit**: curve buy/sell gross event quote, fee-adjusted pricing quote, token amounts, base fee, creator tax, net event/pricing quote flow; median/p75/p90/max per-event quote amounts; same-launch-block, first-three-block and first-30/60-second buy counts; creator role flags and first-seen age; V4 core buy/sell counts and token/quote legs; hook fee amounts in quote or token; unique callers/recipients/swap senders; top-3/5/10 buy-recipient shares; prior tracked-token/event-history counts. Quote amounts are quote-native and must be stratified by quote asset. Hook fees are separate events and must not be double-counted as core swap volume. Prior-history metrics can change with later backfill and need an as-of reconstruction before predictor use. `known_actor_coverage_pct` is zero when directional events exist, and `unique_known_economic_actors` is zero under current semantics; neither establishes trader identity. The `first_60s_curve_buy_count` key in a 30-second feature row is truncated at the 30-second window cutoff; do not treat it as a full 60-second count.

## Leakage classification

| Class | Fields and rule |
|---|---|
| `METADATA_STATIC` | Launch identity/token/quote/curve and deterministic cohort flags; no later-updated stock ticker or final target state. |
| `SAFE_AT_CUTOFF` (event-time only) | The six screened flow metrics, with raw event time no later than cutoff, plus on-chain graduation state only if its block timestamp is no later than cutoff. These remain retrospective until observation-time availability is proved. |
| `FUTURE_ONLY` | T+H price, FDV, market phase, graduation after cutoff, later pool state, future event totals, final target status, and any later market snapshot. They may be labels/diagnostics, never screened predictors. |
| `RESEARCH_DIAGNOSTIC_ONLY` | Feature/target completeness and reason, `finalized_at`, target expiry, provider/cursor/bootstrap state, `data_quality_era`, snapshot delay, updated stock metadata, and prior-history metrics without an as-of ledger. Filtering on completeness is explicitly audited for selection bias. |

## Data-quality eras and selection

Use the completed session `1eb525a3fe2a41b2bab1b5bf8dca4a9a` as the immutable boundary source. `LEGACY_FLOW_ERA` ends at the guarded source stop **2026-09-27 17:38:23.866288 UTC**. `SPLIT_FLOW_ERA` begins at verified post-cutover validation **2026-09-27 17:39:04.824785 UTC**, H_live **74123713**. A launch that started before the split but whose feature cutoff crosses the stop interval is `TRANSITION_ERA`; do not silently assign it to either clean era. The legacy route used the 8 MB Alchemy cap and had activity-dependent missingness. The split route uses PublicNode/Validation WSS and Validation HTTP with proof-backed recovery; improved coverage does not rewrite old `PARTIAL`/`UNAVAILABLE` rows.

At the fixed 2026-09-28 18:43:35 UTC audit snapshot, the 60-second window has legacy quality **436 complete / 95 partial / 95 unavailable** (69.6% complete), versus split quality **59 / 1 / 1** (96.7% complete). Legacy excluded partial rows have a much higher median 60-second raw event count (about 5–6) than complete rows (1); unavailable rows have median zero. This is selection bias, not random missingness. One high-activity split row is partial. Only one usable long-horizon row is already V4 at the feature cutoff, so curve/V4 comparison is descriptive only.

For the 60s cutoff, the conservative pre-label-finalization filter yields **233 usable 6h rows** (217 legacy, 16 split) and **221 usable 24h rows** (all legacy). The 5m/15m pairs have no usable rows under this timing rule; the 1h pair has only 27. These counts support a descriptive preflight, but not a clean split-era chronological train/validation/holdout or a claim of live feature availability at the cutoff.

## Research plan and stop rule

1. Freeze a database snapshot/as-of time; run the aggregate audit with no provider calls. The output includes every valid cutoff/H pair, exclusive exclusion counts, 24-hour maturity, coverage/era/cohort/state counts, p10/p25/median/p75/p90, Spearman screening with deterministic 100-resample bootstrap intervals where N and feature support permit, and feature-tercile outcome medians. Correlation is not causation or a live feature ranking.
2. Keep legacy, transition, and split eras separate. Compare COMPLETE versus excluded by launch hour, cohort, state at cutoff, and raw-event activity. Repeat after enough split-era observations mature; do not fit missingness away.
3. Before modeling, establish a point-in-time feature-availability record and accumulate enough clean split-era 24-hour labels. The audit's conservative readiness check asks for at least 300 split-era 60s→24h rows spanning 30 days before proposing chronological train/validation/holdout. No random shuffle or manufactured test metrics.

Example (run from an isolated copy on Ubuntu; the output file is separate from production DBs):

```sh
python scripts/phase2c_dataset_audit.py \
  --main-db /opt/meme-scanner/data/scanner.db \
  --flow-db /opt/meme-scanner/data/flow.db \
  --as-of 2026-09-28T18:43:35+00:00 \
  --output /tmp/phase2c-summary.json
```

The audit does not produce a raw export, trading policy, or execution logic. Its aggregate JSON is intentionally safe to retain without secrets or raw wallet identities.
